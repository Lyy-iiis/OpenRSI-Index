# Calibrated Failure Probabilities for Frozen CPU Optical Flow

A flow estimate and a probability that it is wrong are different outputs. This task freezes every motion vector and asks whether an agent can estimate the probability of a greater-than-three-pixel error on a new scene. Downstream consumers can then use probabilities for decisions at different operating points.

| Evaluation | Fixed evaluation protocol | Fixed inventory: **40 Work, 40 public pilot, 98 validation, 98 final two-frame pairs**. Work families: alley_1, ambush_5, bamboo_1, market_2, shaman_2. Unused-for-fitting public pilot: bandage_1, cave_2, mountain_1, sleeping_2, temple_2. Validation: all listed windows in bandage_2 and cave_4. Final: all listed windows in sleeping_1 and temple_3. Pilot sibling sequences exist, and no formal validation/test scores are claimed. Missing, corrupt or excluded required input stops provisioning; there is no replacement, truncation or denominator change. Fit in Work, submit once per change, score the candidate only. One CPU thread for prediction; deterministic native-resolution grayscale. 24 hours and at most 24 attempted submissions. Each invalid candidate consumes a slot and receives a finite score of −1000; infrastructure failures are unscored and may retry the identical candidate once. If there is no valid candidate, record a failed trajectory. Select highest validation reward, earliest tie, and run final once. |
| Evaluation | Evaluation mode and input | Direct evaluation of a submitted confidence artifact. Judge generates forward and backward DIS FAST on the two grayscale frames. Query one point every four pixels in both axes, starting at (0,0); exclude official invalid-mask pixels. Target is 1 exactly when Euclidean endpoint error exceeds 3 px. Reverse flow is sampled bilinearly, and an out-of-frame warp has infinite cycle discrepancy for baseline binning. Ground truth is visible only to the scoring side. |
| Evaluation | Reward or score definition | For each scene, sum (p−y)² across all valid grid samples and divide by their count. Loss is the arithmetic mean of the scene losses. Reward = frozen two-signal reference loss minus candidate loss; positive is better, zero reproduces the reference. Also report reliability bins and bad-vector prevalence. No abstention. Final success requires positive reward on the final split and lower loss in both final scenes. |
| Evaluation | Feedback visible to the agent | Validation Brier score and improvement over reference, aggregate ten-bin reliability/counts, class prevalence and validity status. Work labels support detailed diagnosis. |
| Evaluation | Evaluation information hidden from the agent | Judge frames, flow truth, per-pixel labels, per-pair outputs and final test scores remain outside Work. Public scene names and selection rules are disclosed. |
| Evaluation | Measures preventing reward hacking | A frozen copy of confidence/model.json travels with the Judge. It evaluates features and probabilities with its own parser. Candidate JSON cannot contain executable code, stored maps, image signatures or large lookup tables. |
| Evaluation | Noise handling and meaningful improvement | Brier score is deterministic for fixed data, model and pinned build. Compare candidates on the same examples and report paired differences separately for both final scenes. Adjacent pixels and consecutive frames are correlated. Brier measures calibration and resolution jointly; reliability bins help distinguish them. |
