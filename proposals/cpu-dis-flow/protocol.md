# CPU optical flow at the latency of OpenCV DIS FAST

## Research question

Can a two-frame algorithm reuse motion from nearby patches with lower photometric error to improve motion estimates near occlusions, while staying within 10% of the tail latency of DIS FAST? The proposed OpenRSI task would let an agent change the correspondence search, confidence rule, aggregation and refinement in a CPU implementation. This directory supplies a reproducible pilot and an initial candidate.

## Frozen pilot protocol

- Use OpenCV 4.12.0 on one CPU thread, with OpenCL off. All methods receive the same native-resolution, 8-bit grayscale images in temporal order. They have no access to labels, previous flow estimates, or other frames. DIS objects reuse their working buffers between calls. Each inference starts with an empty output flow.
- Use the Final rendering of the public Sintel training data. Select eight frame pairs per scene from four temporal windows. Assign five distinct scene families to development and five others to evaluation according to `pairs.tsv`. All frames of a scene stay together. The official Sintel test set is separate. These small, public splits are suitable for a pilot.
- Compare stock FAST, stock MEDIUM, FAST with one additional variational iteration, and FAST with an extra motion-hypothesis check on a four-pixel grid. The full-grid ablation checks every eligible point. The adaptive version skips checks when the center pixel's absolute photometric residual is below 8 gray levels. Both require a patch cost reduction of more than 12 to accept a new motion.
- Per pair and method, warm up once and take the median of nine timed inferences. Rotate execution order across pairs and repetitions. Time the full inference from grayscale inputs through delivery of the flow field, including candidate postprocessing. Exclude file I/O, color conversion, ground-truth processing and scoring. Use the nearest-rank P95 of the 40 per-pair medians on each split.
- Compute endpoint error (EPE) in pixels against the supplied flow. Pool error sums by valid pixel count. Also score valid occluded pixels and valid pixels less than 10 pixels from the morphological gradient of the supplied binary occlusion mask (3×3 kernel, Euclidean distance). The latter is a pilot boundary metric. It can include pixels on either side of an occlusion transition.
- Before assessing the holdout, fix the candidate, split and acceptance rule. The pilot passes if adaptive has lower pooled all-pixel and boundary EPE than FAST, improves all-pixel EPE in at least three of five held-out scenes, and has P95 no greater than 1.10 times FAST. Repeat the held-out timing run from a fresh process with the same binary and data. Report both runs; both must meet the gate to claim a repeatable pass. Also report the cost and accuracy of all controls.
- For a subsequent OpenRSI run, an independent Judge would own the split, annotations, timing and scoring. The agent would receive development scenes and aggregate validation feedback; final test scenes would be kept outside its workspace. Pilot holdout results are now public and should not serve as a hidden final test. This local executable is a research comparison in one trusted process.
